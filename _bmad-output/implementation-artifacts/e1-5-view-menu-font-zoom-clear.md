## Story

As a MicroBeast operator,
I want font, zoom, and clear controls in the View menu,
so that I can tune the display and wipe the screen without hunting through panes.

**Covers:** FR-9 (font selection — Modern/VT52 ROM/Insigbyte/You Squared/Cushion radio submenu), FR-10 (zoom In `Ctrl+=` / Out `Ctrl+-` / Actual Size `Ctrl+0`; integer 1×..4×; pushed to status bar), FR-11 (Clear Screen + Shift-variant clears scrollback; Clear Scrollback… friction confirm). **AD-7** (menu-bar owns menu-item actions; relocate the same `canvas.js` setter + `savePrefs` the old handler called; `applyThemeSideEffects`'s font *hiding* becomes menu-item **enable/disable**), **AD-9** (neutral shell; CRT-font items shown-but-`data-disabled` off-CRT — replaces the incumbent `#font-row` hide), **AD-3** (import allowlist — `menu-bar.js` may import `canvas.js` setters + `state/prefs.js`), **AD-4** (prefs SSOT — `savePrefs` write / `getPrefs` read-at-use), **AD-6** (status bar is fed, never owned — zoom mutation owner imperatively pushes `statusBar.setZoom()` at the setter site; no-op until E4), **AD-13** (`chrome.js` retained/slimmed — the zoom **chord** stays; only the **Clear** handlers + the **font selector** action leave), **AD-14** (reset re-projection — `projectPrefs` fills its font/zoom half; `applyPrefs` keeps one `setFont`/`setZoom` call each).
**Depends on:** E1.1 (`menu-bar.js` shell + `#dropdown-view` markup) — **done**; E1.2 (keyboard nav + Esc-guard) — **done**; E1.3 (`clearScreen`/`clearScrollback`/`wireClearButtons` already in `menu-bar.js`; `projectPrefs` seam; `applyPrefs` decomposition; boot order) — **done**; E1.4 (the radio-submenu mechanic + `syncPhosphorDisabled` + `projectViewOnOpen` — the exact templates this story reuses) — **done**; E0.1 (`retainFocus`) — **done**; E0.2 (`openModal`) — **done** (used by the Clear Scrollback confirm — see AC-4).

## ⚠️ Scope Decision — READ FIRST (this is the LAST E1 story; it closes out the View menu and retires the last incumbent View controls)

This story finishes the View menu. It relocates the three remaining incumbent controls into `#dropdown-view` and retires them from their old homes, reusing — not rebuilding — the radio-submenu mechanic E1.4 stood up. Six scope pins:

1. **Reuse the E1.4 radio-submenu mechanic verbatim for Font.** E1.4 built `openSubmenu`/`closeSubmenu`/`submenuItems`/`moveSubmenuFocus`/`onRadioSelect`/`setRadioChecked` (`menu-bar.js:392-533`) and proved them on Theme + Phosphor. Font is the **third** radio submenu and needs **zero new mechanic** — only (a) the child-panel markup (`data-submenu="font"` + `data-submenu-panel="font"` with 5 `menuitemradio` rows), and (b) a `font` branch in `onRadioSelect`. Today the Font parent row (`index.html:1032-1034`) is a bare placeholder with **no `data-submenu` key and no panel**, so `panelForParent` returns null and `openSubmenu` no-ops (`menu-bar.js:395-396,412`). Fill it.

2. **Font is CRT-only — SHOWN-but-`data-disabled` off-CRT, mirroring Phosphor (AD-7, AD-9).** ⚠️ **DECISION — see the reconciliation note in Dev Notes.** The incumbent `#font-row` was **hidden** under the Console/Clean theme (`applyThemeSideEffects`, now the temporary `main.js onThemeChange` gate). AD-7 (`:103`) and AD-9 (`:114`) both say that hide becomes menu-item **enable/disable**: "the Phosphor **and CRT-font** menu items are shown but **disabled** (`data-disabled`) when the Console/vector theme is active." So the Font submenu parent is `data-disabled` (skipped in nav, announced via `#menu-bar-live`) whenever Theme ≠ CRT — **exactly** the Phosphor treatment E1.4 built (`syncPhosphorDisabled`, `menu-bar.js:518-533`). Add a parallel `syncFontDisabled`. (The E1.5 AC in `epics.md:354-356` and EXPERIENCE.md `:51` are *silent* on gating — they neither require nor forbid it; the governing **architecture** decides, and it says disable. This preserves the incumbent "font is inert on the vector renderer" behavior.)

3. **Zoom chords STAY in `chrome.js` (AD-13, SACRED).** Do **not** move or rewrite the `Ctrl+{=,-,0}` chord block (`chrome.js:127-147`). The new View ▸ Zoom **items** call the **same** `canvas.js` functions the chord calls (`zoomStep(+1)` / `zoomStep(-1)` / `resetZoom()`) + the same `savePrefs({ fontZoom })`. The only additive touch to the chord block is one `pushZoom(...)` line per branch, right beside the existing `savePrefs` line, so the shortcut path also feeds the status bar (FR-27 "either way"). Nothing else in the SACRED `chrome.js` set is touched.

4. **Clear behavior already exists in `menu-bar.js` — reuse it, repoint the wiring.** E1.3 already put `clearScreen({ alsoScrollback })` (`:125-136`) and `clearScrollback()` (`:138-147`) into `menu-bar.js`, wired to the **DOM buttons** via `wireClearButtons` (`:153-164`). This story **repoints** those handlers from the removed `#clear-button`/`#clear-scrollback-button` onto the View ▸ Clear Screen / Clear Scrollback… **menu items** (via the action-dispatch in `onItemClick`). The clearing functions themselves are **unchanged**. Do **not** rewrite them.

5. **Retire the three incumbent controls (relocation = delete, per the E1.4 precedent).** Delete `#font-row`/`#font-select` (`index.html:1247-1257`, in `<details id="settings">`) + its `chrome.js` wiring (`:217-235`) + its `applyPrefs` DOM mirror (`main.js:1105-1106`); delete `#clear-button` (`index.html:1119-1120`, in `#top-bar`); delete `#clear-scrollback-button` + hint (`index.html:1284-1285`, in `<details id="settings">`). Delete the **temporary `#font-row` CRT-gate line** (`main.js:181-182`) — but **keep the rest of `onThemeChange`** (its `menuBar.projectPrefs()` call still drives Theme/Phosphor **and now Font** re-projection on a theme change/chord).

6. **`#top-bar` and `<details id="settings">` are NOT removed here.** `#top-bar` keeps `#connect-button` (E2), `#send-file-button`/`#send-file-input`/`#paste-progress-row` (E3/E7); its full deletion is E7. The Settings `<details>` keeps `#local-echo`, `#enter-key-sends`, `#reset-prefs-button` (E3). Only the **font-row + the two clear buttons** leave. Do **not** wire Local echo, Enter-key-sends, Reset, Connect, or Send File here — those are E2/E3. **Do not front-run** (the E0 retro flagged repeated front-running twice in this epic — `epic-e0-retro-2026-07-01.md`).

**One-line summary:** E1.5 = add the Font child-panel (5 radios) + `font` branch in `onRadioSelect` (reusing the E1.4 submenu mechanic, Font `data-disabled` off-CRT via a new `syncFontDisabled`); wire View ▸ Zoom In/Out/Actual Size to `zoomStep`/`resetZoom` + `savePrefs({fontZoom})` + `clearSelection` + a no-op `pushZoom` status hook; wire View ▸ Clear Screen (+Shift→scrollback) / Clear Scrollback… (friction confirm) to the existing `clearScreen`/`clearScrollback`; fill the font/zoom half of `projectPrefs`; and retire `#font-select` + `#clear-button` + `#clear-scrollback-button` — while the `Ctrl+{=,-,0}` and `Ctrl+Alt+T` chords stay in `chrome.js`.

## What must NOT be lost (FR-6 / NFR-3 carry-over — pin these before you delete anything)

- **Font application + persistence.** The incumbent `#font-select` change handler called `setFont(value)` + `savePrefs({ font: value })` (`chrome.js:227-229`). Relocate that **verbatim** into the `font` branch of `onRadioSelect` (AD-7). `setFont` is idempotent (same-value short-circuit, `canvas.js:582`) and rejects unknown ids (`atlasSetActiveFont` guard) — do not add extra guards.
- **Boot/reset font application stays `applyPrefs`'s single-writer job (AD-14).** `applyPrefs` calls `setFont(p.font)` (`main.js:1104`) — **keep it**; only delete the `#font-select` DOM mirror below it (`:1105-1106`), which references a now-removed element. `setFont` must still be invoked from exactly one place on reset.
- **Zoom persistence + integer clamp.** The chord persists via `savePrefs({ fontZoom: getActiveZoom() })` and clamps to 1..4 inside `zoomStep`/`setZoom`/`resetZoom` (`canvas.js:531-569`). The menu items must produce **byte-identical** results — same functions, same persist, same clamp. `zoom.spec.js` (the SACRED chord oracle) must stay green.
- **The D-19 selection-clear on zoom change.** Zoom is a D-19 trigger (selection clears on theme/phosphor/**zoom** change). The chord path clears via the capture listener at `main.js:361-369` (**keep it** — the chord is unchanged). The new View ▸ Zoom **menu items** must **also** clear the selection, via the already-injected `clearSelection` opt (`clearSelectionRef`) — mirroring how E1.4 rehomed D-19 onto the Theme/Phosphor menu actions. (Font selection is **not** a D-19 trigger — do **not** clear the selection on a font pick.)
- **Clear Screen semantics + the Shift variant (D-26/D-15/D-04).** `clearScreen({ alsoScrollback })` wipes the visible 80×24 via `term.clear_visible()` (NOT `\x1B\x4A` — parser state untouched), optionally wipes scrollback via `resize_scrollback(0)→(10000)`, and snaps to bottom. The **Shift** variant (`alsoScrollback: e.shiftKey`) must survive the button→menu-item move — thread the click event's `shiftKey` through `onItemClick`. `clearScrollback()` wipes scrollback only, leaving the grid untouched. `clear-screen.spec.js` oracles pin all of this.
- **`onThemeChange`'s re-projection survives.** After you delete `fontRow.hidden = (name !== 'crt')` (`main.js:182`), the helper's remaining `menuBar.projectPrefs()` call is what re-derives the View menu (Theme check, Phosphor `data-disabled`, **and now Font `data-disabled`**) after a `Ctrl+Alt+T` chord or a menu theme change. Keep it; `projectPrefs` now derives Font's disabled state too.

The two theme/zoom chords, focus indicator, visibilitychange BEL-title-strip + repaint, and pagehide/visibilitychange SLIDE `CTRL_CAN` safety in `chrome.js` are the E1.3 SACRED set — **do not go near them** beyond deleting the font-selector block (§Task 3) and adding the one `pushZoom` line per zoom-chord branch (§Task 2.4).

## Acceptance Criteria

1. **View ▸ Font radio submenu applies + persists the font; the radio reflects the active font (FR-9; AD-7).**
   **Given** the View ▸ Font submenu (`Modern (8×16)` · `VT52 ROM (8×8)` · `Insigbyte (8×8)` · `You Squared (8×8)` · `Cushion (8×8)`) opened from the `#dropdown-view` Font row
   **When** the user selects a font (by click or ↑/↓+Enter)
   **Then** `menu-bar.js` calls `setFont(value)` + `savePrefs({ font: value })` (the exact setter+persist the retired `#font-select` handler called — `chrome.js:227-229`, relocated verbatim), the active radio's leading check glyph (`✓` in `.check`, `chrome-accent`) moves to the chosen row (siblings deselected), the canvas re-rasterises in the chosen font, and the choice persists across reload
   **And** `data-value` on each radio is the exact atlas id (`modern`·`vt52`·`insigbyte`·`you-squared`·`cushion`, matching `FONT_IDS` — `atlas.js:41`); the menu (and submenu) stay open on select (radio semantics, AD-7).

2. **View ▸ Font is shown-but-`data-disabled` under the Console/Clean theme; live under CRT (FR-8 sibling behavior; AD-9).**
   **Given** the View ▸ Font parent row
   **When** Theme = CRT
   **Then** the row is live: selectable, keyboard-navigable, opens its submenu
   **And when** Theme = Console (Clean), the Font **parent row** is `data-disabled` (`chrome-muted`, no hover fill), `aria-disabled="true"`, **skipped** in keyboard nav, **announced** via `#menu-bar-live` (title e.g. `"Font — CRT theme only"`), and never opens its submenu — replacing the incumbent `#font-row` *hide* (AD-9). The enable/disable tracks the live theme mid-menu (switching Theme→CRT enables Font in the same interaction; Theme→Console collapses + disables it), projected by the theme-select handler and `projectPrefs`, not a reload.

3. **View ▸ Zoom items match the chord exactly and feed the status bar (FR-10; AD-6; AD-13).**
   **Given** the View ▸ Zoom items — `Zoom In` (hint `Ctrl+=`), `Zoom Out` (hint `Ctrl+-`), `Actual Size` (hint `Ctrl+0`)
   **When** the user activates them by item **or** shortcut
   **Then** zoom changes in integer steps clamped 1×..4× **identically** either way — the items call `zoomStep(+1)` / `zoomStep(-1)` / `resetZoom()` (the same `canvas.js` functions the SACRED chord calls, `chrome.js:129-146`), persist via `savePrefs({ fontZoom: getActiveZoom() })`, and clear the selection (D-19) via the injected `clearSelection`
   **And** the new level is offered to the status bar via an imperative push hook (`pushZoom(getActiveZoom())`) fired at the setter site on **both** the menu-item path and the chord path — a no-op stub injected by `main.js` until E4 consumes it (AD-6); the `Ctrl+{=,-,0}` chord block itself is otherwise untouched (AD-13).

4. **View ▸ Clear Screen wipes the visible grid (Shift also wipes scrollback); Clear Scrollback… requires a friction confirm (FR-11; AD-13).**
   **Given** the View ▸ Clear Screen item
   **When** the user activates it
   **Then** `clearScreen({ alsoScrollback: e.shiftKey })` runs (the existing `menu-bar.js:125-136` handler, repointed from `#clear-button`): a plain activation wipes the visible 80×24 (`term.clear_visible()`, parser state untouched, snap-to-bottom) leaving scrollback intact; a **Shift**+activation also wipes scrollback (`resize_scrollback(0)→(10000)`, D-26); the item closes the menu (action variant)
   **And given** the View ▸ Clear Scrollback… item
   **When** the user activates it
   **Then** a **deliberate-friction confirm** appears showing the verbatim copy **"Wipes the 10,000-line history."** before anything is wiped; only on confirm does `clearScrollback()` run (scrollback flushed via `resize_scrollback(0)→(10000)`, visible grid untouched, snap-to-bottom); on cancel nothing changes. (See Dev Notes "Clear Scrollback confirm" for the confirm mechanism — the shared `openModal` path is recommended.)

5. **`projectPrefs` re-projects font (+ its disabled state) on reset, idempotently and without throwing (AD-14; AD-4).**
   **Given** `menu-bar.js projectPrefs(prefs)` — whose font/zoom body E1.3/E1.4 left as a no-op (`menu-bar.js:730-731`)
   **When** `resetPrefs()` fires (or `projectPrefs` is called at boot, `main.js` prefsSubscribe registration, and on every View-menu open via `projectViewOnOpen`)
   **Then** it projects `p.font` onto the Font submenu's active-radio check glyph and re-derives the Font parent's `data-disabled` from `p.theme` (via `syncFontDisabled`) — reading prefs **at use-time** (passed blob → `getPrefs()` fallback), **never** calling `setFont`/`setZoom` (those stay `applyPrefs`'s single-writer job), **never** writing top-level open/close state (`render()` remains sole writer), and **never** throwing on absent DOM
   **And** calling `projectPrefs` twice yields identical DOM (idempotent). The **zoom** half has no persistent menu-DOM to project (zoom items are stateless actions; the level surfaces in the status bar, E4) — the reset zoom→status push is `applyPrefs`'s job at its `setZoom` site (AD-6/AD-14), so the zoom half stays a documented no-op here.

6. **Incumbent controls retired; no behavior lost; boot order + single-writer preserved (FR-6; NFR-3; AD-13; AD-14).**
   **Given** the migration is complete
   **When** the app boots and on `resetPrefs()`
   **Then** `#font-select`/`#font-row`, `#clear-button`, and `#clear-scrollback-button` are **absent** from the DOM; the font-selector wiring is **gone** from `chrome.js` (grep-clean: no `getElementById('font-select')` / `setFont` import remains in `chrome.js`); `applyPrefs` no longer references `#font-select` and still calls `setFont`/`setZoom` exactly once each on the reset path (no `null` throw); the temporary `#font-row` CRT-gate line is deleted while `onThemeChange`'s `projectPrefs()` re-projection survives; the `Ctrl+{=,-,0}` + `Ctrl+Alt+T` chords still fire (menu-bar wired before `wireKeyboard`); and the four SACRED `chrome.js` behaviors are untouched.

7. **No regression; suite green; test hooks intact (FR-6; NFR-6; AD-2).**
   **Given** the migration + Font submenu are in place
   **When** the full Playwright chromium suite runs
   **Then** the incumbent oracles — retargeted onto the menu path — stay green: `clear-screen.spec.js` (Clear Screen via menu, Shift→scrollback, parser-state-untouched, snap; Clear Scrollback via menu confirm), `zoom.spec.js` (SACRED chord oracle unchanged + clamp), and a new font oracle (apply+persist+radio-check + disabled-off-CRT); the `view-theme-phosphor.spec.js` `#font-row` gate test is updated to assert the Font-submenu `data-disabled` (the `#font-row` element is gone); the SACRED `chrome.js` set stays green — judged by **named oracles in isolation** (`--workers=1`) where the pre-existing parallel-load/wasm-boot flake interferes (E0 action item #1)
   **And** `window.__menuBar.__getStateForTests()` still exposes the E1.1–E1.4 shape (Font uses the same `openSubmenu`/`submenuFocus*` introspection as Theme/Phosphor), and new/extended specs cover AC-1..AC-6.

The AC requires *a* deliberate-friction confirm showing `"Wipes the 10,000-line history."`; it does not mandate the mechanism. **Recommended: `openModal` (E0.2).** Rationale: (1) the `…` suffix denotes a dialog across the whole IA (`Send File…`, `Keyboard Shortcuts…`, `About Beastty…`, `Serial Configuration…`); (2) an irreversible history wipe deserves an explicit modal, not a subtle label-swap buried in a closing dropdown; (3) `openModal` is the sanctioned, proven shared path (E0.2), so no new confirm mechanic is invented; (4) a dropdown-internal 2-click confirm is fragile — click-away/`closeMenu` disarms it. **Before adding markup, grep for an existing reusable confirm helper** (the SLIDE flow has a modal confirm) and reuse it if its signature fits; otherwise add a minimal `<dialog id="clear-scrollback-confirm">`. **Documented fallback** (only if a modal is judged over-scope): the inline 2-click pattern from `chrome.js:265-291`, adapted so the menu stays open after the first (arming) click and commits on the second.
