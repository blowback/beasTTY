## 1. Summary

E11 shipped the whole gesture: select a filename in one beast's terminal, drag it onto the other beast's
terminal in a second Chrome tab, confirm, and the file crosses. No server, no protocol change, no firmware
change, no pane, no peer list. Identity rides in the drag (a versioned custom `dataTransfer` type carrying a
session id and a single-use nonce); the bytes ride a same-origin `BroadcastChannel`.

Shipped in dependency order, which is not numeric order: **S11.4 → S11.1 → S11.2 → S11.3.**

## 2. What went well

- **The two-phase exchange was the right call, taken before any code.** S11.2's create-story pass established
  that one deadline cannot cover both "did anyone answer?" and "did the file arrive?" — the reply is
  instantaneous (0–2 ms, measured) and the SLIDE pull behind it is not. So: an immediate `accepted`/`refused`
  under a single non-chained deadline, then the files with no deadline at all, with a `bye` on `pagehide`
  covering the tab that dies after accepting. Every one of S11.2's four review findings then landed in the
  one window that design creates — what this tab owes a requester after it has posted `accepted` — which is
  exactly where a reviewer should have been looking, and was.
- **Refusals are codes, never sentences.** `peer-link.js` added no user-facing string anywhere; the frozen
  `PEER_REFUSAL_CODES` set travels and S11.3 owns every word. That kept the copy decisions in the one story
  with a copy budget, and made the whole refusal mapping a pure function drivable by spec without a channel.
- **Fail-closed defaults throughout.** An absent or throwing `isBusy` getter reads as **busy**; a malformed
  payload becomes `pull-failed` rather than reaching S11.3 as something it will try to build a `File` from;
  an unwired harness refuses rather than handing out files. The module assumes it is broken, not fine.
- **Structural specs as architecture enforcement.** `peer-link.js` has a spec that reads its own source,
  strips comments, and fails on any `import`, any `document`, any `window.*` beyond the pagehide add/remove.
  `peer-drop.js` has one asserting no `setInterval`, exactly two `setTimeout` sites, and no self-re-arming.
  These pin rules that no behavioural test can reach.
- **Each story corrected its own epic before writing code.** S11.1 found three corrections, S11.2 five,
  S11.3 seven. Several would otherwise have surfaced late and expensively — the epic named
  `pullProgramFromAutoSend` three times and no such identifier has ever existed; the epic's AC-2 was about a
  picker that was already there. This practice is quietly carrying the whole workflow.

## 3. The headline — one unrepaired shape, seven appearances

**The recv-only predicate.** `slide-recv.js`'s `isSlideActive()` only sees sessions that were handed a
`slideRef`, which send sessions never are. Every consumer that wants "is a SLIDE session running?" must
independently notice this and compose the right predicate. In E11 alone:

| Where | Outcome |
|---|---|
| S11.4 review #1 — `maybeExitRecvMode` has no `CancelPending` arm | Send cancel lost the peer's echo; review called it "the third instance" |
| S11.2 §3(b) — `isBusy` for the peer status query | **Took the correct branch deliberately**, citing the leak having already happened three times |
| S11.3 — `hasBoundFolder`, and the composite it spec-asserts at the composition root | **Correct**, with a spec pinning the composition |
| `main.js` `wireChrome` — recv-only `isSlideActive` **and** a recv-only cancel | Wrong. Raised by S11.4's review, re-carried by S11.2, re-carried again by S11.3 |

That last one is the epic's only defect that reached a user-visible consequence unrepaired: closing the tab
mid-**send** emitted no `CTRL_CAN` and left the Z80 waiting — and since S11.4 made `pagehide` the sole
hide-time trigger, it was the *only* remaining teardown protection. **Fixed post-epic in `b9827ab`.**

The lesson is not "three stories forgot." Two of the three noticed and got it right; the third
deliberately declined because `chrome.js` was on its no-change list. The lesson is that **a predicate whose
correct use requires every consumer to know a piece of folklore will eventually meet a consumer who doesn't.**
The repair is at the source, not the call site — one exported composite, with the recv-only one made
module-internal. That is the single action item E11 opens.

## 4. Second theme — six specs that passed for the wrong reason, and the one practice that caught them all

| Story | The spec, and why it was lying |
|---|---|
| S11.1 | AC-2 asserted `data-state="disconnected"`, which `index.html` ships in static markup — it resolved before a line of `main.js` ran and raced the boot scan it existed to observe |
| S11.2 | Five "unusable provider" cases compiled providers with `new Function`; CSP blocked every one, and *a provider that throws is itself one of the five cases* — all five reported the case they were named after without ever building the payload |
| S11.4 | The mock bot never echoed `CTRL_CAN` in its recv role, so no page-initiated send cancel had **ever** been answered in any spec; and the console assertion read too early, before the 2 s hatch fired |
| S11.3 | The `~N` case used `WOTBEAST.FTH`, and file-source's own 8.3 truncation repaired `WOTBEAST~1.FTH` straight back — the wrong name reached the device and the assertion passed |
| S11.3 | The hidden-mid-pull case stayed green with the landing counter broken, because a 1.5 s backstop settled the wait and the read-back still found the file |
| **This retro's own fix** | The new pagehide send case asserts the session ends, but reverting the cancel-routing half leaves it **green** — the raw `writeSlideFrame(0x18)` alone suffices, because the mock bot echoes `CTRL_CAN` and the state machine unwinds on the echo |

**Every one was caught by mutating the fix and requiring red — not by review, not by reading.** Twelve
mutations in S11.3 alone, five in S11.2, five red-first cases in S11.4. This is the epic's most productive
practice and it is entirely undocumented; it lives in whoever happens to be doing the story.

Note the last row: the practice caught a spec of mine, mid-retrospective, in the act of overclaiming. It is
recorded in the spec's own comment rather than quietly left to read as coverage it doesn't provide.

## 5. Third theme — hardware found what the suite structurally cannot, exactly as E9 predicted

The E9 retro's headline was *"our simulated realities were more forgiving than the real ones."* E11 ran two
checkpoints and both paid:

- **S11.1's T5.** The shipped in-use classifier keyed on `InvalidStateError`. Real hardware says the cross-tab
  rejection is `NetworkError` — **so the branch written for that case had never once fired for it**, and its
  only spec hand-fed a message no real rejection produces. Two independent defects in one four-line branch,
  each of which concealed the other.
- **S11.3's AC-15.** Playwright drags are synthetic — a `new DataTransfer()` has no protected mode — so the
  real Chromium drag loop had never been exercised. That the overlay lights on B at all is the proof the
  custom type survives a native cross-tab drag. It also found the modal's `To` row naming drive `A:` while
  the receiving beast was on `B:` (`{X}` was `slideProgramDrive` — where SLIDE.COM *lives*, not where CP/M
  writes). Ant's call was to delete the drive rather than qualify it; the dependency went with it.

**A row that states a fact the app does not have is worse than a row that states less.** Worth keeping.

## 6. Fourth theme — prose that lied about wired code

`slide-chip.js`'s `onStateChange` is described as the chip lifecycle fan-out by its own module header **and**
by `slide.js:319`'s subscribing comment. Since Plan 11-04 it has carried exactly one event kind,
`'inline-action'`. S11.3's story planned against the description, and the fan-out had to be built mid-story.

This is adjacent to E9 action #3 (the dormant-hook sweep) but the more expensive class: a dormant hook wastes
code, whereas **stale prose causes a story to be planned wrong.** The story-writing process reads comments as
specification, which is mostly a strength and precisely why the failure is costly.

## 7. Fifth theme — two review findings, one blind spot

S11.3's two serious findings both sat in `pullForPeer`'s wait and were invisible for the *same* reason: the
suite runs one pull at a time, through a directory stub that enumerates in insertion order, with alphabetical
fixture names.

1. **The read-back paired directory order against command order.** A two-file drag of `ZAP.COM ABC.TXT`
   handed the peer a `ZAP.COM` containing `ABC.TXT`'s bytes and vice versa — silently, both transfers
   reporting success. The only finding in the epic that could **corrupt a user's files** rather than
   mis-report. "Arrival order = command order" was recorded in the Dev Notes as an assumption; it was wrong
   on the read-back side, and the multi-file pin held only because that fixture's names happened to sort.
2. **A stale auto-hide failed the *next* pull.** Every summary/error/notice arms a 5 s auto-hide that emits
   `'hidden'`, so two drags inside 5 s had the first transfer's auto-hide settle the second pull's wait early
   and report `pull-failed` about a pull running perfectly.

Both need a fixture the suite doesn't have: non-alphabetical names, non-insertion-order enumeration, and
back-to-back sessions. Recorded here as a known coverage gap rather than opened as an action (Ant's call on
scope), and worth remembering the next time this surface is touched.

## 10. Known limits carried out of E11

Each was recorded deliberately in its story, not discovered here:

- **`enterNotice` can clobber a live progress chip** (`slide-chip.js`). A late `pull-failed` sentence can
  arrive after this tab has started its own transfer and hide it 5 s later. Needs a precedence rule between
  notices and live progress — a UX decision, with the copy frozen by UX-DR7. **Owner: Ant.**
- **`isPortInUse` treats every `NetworkError` as a cross-tab hold.** A present-but-wedged adapter, or a Linux
  user not in `dialout`, will be told to hunt for a phantom tab. The message is a verbatim AC; the real
  answer is a `BroadcastChannel` probe nobody has written the copy for.
- **The boot cue hardcodes "MicroBeasts" but counts stored-preset matches** — two CH340 clones granted via
  "Show all serial devices" read as "2 MicroBeasts detected". Verbatim AC.
- **`slide-recv.js:528` fires `onFileLanded` on the anchor-tray path.** `downloadToFolder` returns without
  throwing when it finds no handle, so the callback's name is a lie there. The resulting outcome stays honest
  (`pull-failed`); only the diagnostic misleads. Observed in S11.3, reconfirmed in its review, out of scope
  both times.
- **A hard-killed tab strands a requester.** No `bye` is posted on a process crash, and a requester waiting on
  an already-accepted request waits indefinitely. Not papered over with a poll — a poll is the shape S11.4
  removed.
- **An expired reply deadline tells the responder nothing** — it still runs a full SLIDE pull nobody awaits.
  Ending that needs a fifth message kind.
- **The 126-char SLIDE command cap** silently pulls fewer files than a large multi-file drag asks for. The
  decision taken: pull what fits, return what landed.
- **Deep-backgrounding remains unobserved on hardware.** S11.3's checkpoint hid the tab ~10 s, which
  exercises the basic clamp but not Chromium's coarser post-~5-minute regime.
