- (outcome) 2026-08-05 designed 'beast-to-beast drag' (E11 candidate): select a filename in beast A's terminal, drag it onto beast B's terminal in another TAB/WINDOW of the same browser, B's device receives it. Mechanism: at dragstart A stamps its own session id into a custom dataTransfer MIME alongside the filename (custom types survive cross-window in one browser; a JS-built File does NOT — S9.4 proved Chromium strips it); B's drop reads the id and asks that exact tab over BroadcastChannel; A runs SLIDE S, posts the Blob (structured-cloneable, files are KB), B feeds enterSendMode. No server, no disk hop, no presence pane, no nicknames — the drag carries the identity so the 'which beast is this' problem never arises (getInfo() gives VID/PID only; two MicroBeasts are byte-identical, serial.js:46 — 'ttyUSB6' is unobtainable, ever). Honour the existing 'Confirm file transfers' pref (prefs.js:62) on B's side; that modal doubles as the only place the feature explains itself (Paige's concession after losing the pane). Known blocker to fix FIRST, on its own merits: serial.js:236 ports.find() first-match-wins means two tabs both latch the SAME port. Second prerequisite: waitForSendState (slide.js:1177) and the recv twin (slide-recv.js:693) poll setTimeout(tick,10) against a deadline — in a hidden tab the clamp makes the TIMEOUT win, so a backgrounded tab reports a failure that did not happen; fix = resolve on the state transition. Real sleeps (INTER_FILE_HEADER_DELAY_MS=500, slide.js:1430) are minimums and stretch harmlessly; canvas.js:425 rAF is paint-only so a hidden tab still parses.
